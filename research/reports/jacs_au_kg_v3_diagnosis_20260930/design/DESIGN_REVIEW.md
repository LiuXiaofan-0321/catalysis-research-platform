# KG-v3 3×3 设计与反馈复核

日期：2026-09-30。独立只读检查代码和 9 条主试跑 JSON，并用原生训练特征重放数值检查；未运行 API、训练或服务器作业。量化结果见 `design_audit.json`，复核程序见 `audit_design.py`。

## 结论

当前 1.06 个百分点的 KG—Agent 评分差不足以归因于 GLM 太强。更直接的设计缺陷是：未告知真实变量支持域、科学检查拒绝后缺少同轮修复、长且固定的证据包、没有保持独立于检索的探索分支，以及图只作为提示中的六张机制卡，未承担约束执行和决策工具。

RAG 明显损失的是可执行候选。27 个提案仅 11 个拟合，15 个数值不稳定拒绝均可在真实零值上重现。不是出错的训练器，也不是输出长度截断。KG 完成 17 个拟合，已经高于 Agent 的 16 个，因此 KG 与 Agent 的剩余差距还涉及有效公式质量、变量解释和随机搜索，不可简单归为“测试太少”。

## 一、真实零值与公式支持域没有进入生成提示

训练集 2,361 行中的零值：

| 变量 | 精确零值 | 比例 | 数据特征 |
| --- | ---: | ---: | --- |
| PBF | 587 | 24.86% | 多种平面/少重原子分子 |
| PMI1 | 113 | 4.79% | ethene 59 + methane 54；近零另有一批 |
| PMI2/PMI3/SPAN/GeDi | 各 54 | 2.29% | 全部 methane |
| ASA/AV | 各 28 | 1.19% | LTN/UOZ/ACO/NON/SGT/ANA 六类框架 |

这里的分子零值要按原文去氢/隐式氢代理理解；不能说真实甲烷的全原子惯量为零。原始 D0 保持不变，新公式必须正确处理这些代理的退化情形。

例如 `log(q_MW)-log(q_AV)` 的 28 个非有限值全部来自 AV=0；声明范围是全训练集，稳定性 98.81% 刚好低于 99% 门槛。多个涉及 PMI 的 log 比值在甲烷/乙烯上失败。不能把所有“unstable”解释成深奥机理错误。

代码 `run_jacs_au.py:307` 给生成器变量字典、机制要求和符号规则，没有提供训练 min、零值比例、分位点和非零适用域。`scientific_check` 要求声明区域内至少 99% 有限，随后 `checked_feature` 仅要求全训练集至少 95% 有限并使用训练中位数填充。两个门槛承担不同目的，但现在没有向模型说明清楚，泛称拒绝也不告诉它哪个变量、多少行失败。

修复应保留检查，并让三个条件都收到同样的训练特征支持域摘要。对域失败提供机器结构诊断，例如 `AV_zero_fraction=0.0119; invalid_operator=log; regime_valid_fraction=0.9881`。允许每轮在训练侧、拟合前做一次限定修复，保持同一机制、同一证据、固定方向声明；禁止因为评分不理想重试。记录初始提案和修复提案，以初始 3 个科学假设为预算单位，并单独报告新增 API 成本。

不能仅把 99% 改成 95% 让排名好看。对真正退化的分子代理需要明确数值极限/平滑的代理含义；对 AV=0 的探针不可达框架，要承认 AV 并不一定等于目标分子的真实可用体积。任何 `+1` guard 都只是参考归一化后的数值/代理设计，不构成物理依据。

## 二、检索反馈没有改变事实集合

v3 每轮都拿到全部 23 张 RAG 卡，KG 再得到全部 6 张 KG 卡。`adaptive_query` 会用保留机制和拒绝信息重新排序，`select_evidence` 的预算可容纳整个银行，所以事实集合、词 token 和路径数不变。

这支持“没有删减掉 RAG 锚点”这个工程修复，但当前行为仍接近固定长上下文条件生成。下一轮需要的“methane 惯量退化”“AV 探针不可达”“自由球与沿路径内接球区别”不会因为查询而从新来源补入。将 query 变长不会解决此问题。

应采用稳定证据锚点 + 按本轮具体缺口调用支持域/变量语义/反例工具，并保留完整出处可展开。压缩视图要保持同一事实、限定条件和反证，且对 flat 与 graph 用相同事实。首先比较结构化短卡与当前完整长包；不要同时换证据、换模型、换图、换预算，然后把提升归于 KG。

## 三、科学方向通过不代表变量含义正确

源文及 Zeo++ 的语义应明确成三个概念：Df 最大自由球/可通过瓶颈的尺寸；Dif 沿自由路径上的最大内接球尺寸；Di 全局最大内接球。不能把 largest free sphere 解读成全局最大孔腔，更不能因为 f<p 就认定原始列反了。

当前字典 `lsd_f`/`lsd_p` 的短描述不够明确，生成记录出现相反解释。例如 KG 第 2 条保留 `q_lsd_p-q_lsd_f` 时，把 `lsd_f` 说成最限制的局部球并声称两个独立归一化变量使用同一中位数尺度；后者明显不成立。Agent 与 KG 也出现将 p 当窗口、f 当孔腔的陈述。有限差分只检查公式与声明方向，不检查原始变量究竟测量什么。

此处最适合 KG 提供真实帮助：为输入节点保留 source definition、测量方式、单位、零值含义和适用域；公式中的每个物理断言先做 typed mapping 检查，再形成候选。不用预测 MAE 确认这些规则。局部方向和训练 Spearman 继续作为诊断，不宣称因果验证。

## 四、检索组替代了 Agent 的生成分布

当前三组分别独立生成 3 个公式。加入证据改变整个提示和生成分布，不保留 Agent 的候选，也不保证 RAG 是 Agent 候选的超集、KG 是 RAG 的超集。因此输入证据增加，最优候选质量仍可能下降。

“KG 包含 RAG 全部事实”与“KG 保留 RAG/Agent 的候选能力”不是一回事。知识可能缩小探索到熟悉的 log/旋转路径，也可能把注意力引到当前代理无法表达的机制。RAG 21/27 提案含 log，Agent 7/27；这是一种可观察的分布变化，但不能单凭此数字证明长证据引发锚定。

保持 3×3 的公平主实验可每轮共享一个不看证据的 blind 候选，另外两个槽分别由 Agent 自主、RAG、KG 工具产生；初始共用候选只生成一次，成本统一分摊，后续当前保留状态独立。这样保护一部分独立探索，仍然不能保证排名，也不会暗中给 KG 9 个候选、Agent 3 个候选。

另一项可预先冻结的主设计是三个 blind 假设槽之后进行一次复核：Agent 使用无外部证据的自检，RAG 使用文本证据复核，KG 使用变量约束/条件关系复核；每槽只允许保持同一假设的修正，最终每轮仍拟合三个候选。失败修复调用上限和训练侧检查完全一致。保留修正前/后表达式与拒绝理由，不能把三个原式和三个修正式全部拟合再宣称只有三候选。有效原式被有效修正式替换仍可能损失预测能力，所以此设计改善能力继承，不能保证排名。

若希望完整继承 Agent 已找到的所有候选，可做扩展候选池/保留整条 blind 分支的另一个实验。但它增加 API、拟合次数或搜索分支，必须给无知识控制同样成本，报告 knowledge-only 的新增边际收益。候选超集在相同当前状态下保证评分最优值不下降；独立贪心路径、未知测试集和泛化均不受这个保证保护。不要把机械继承造成的评分顺序当作 KG 知识有效的证据。

## 五、拟合与统计的实际限制

相同 D0、固定评分划分、固定 4,000 epoch 与 seed3、相同检查，对三组是对称的。当前排名不是因为 KG 用了较差的预测器。但不同新增维度重建 ANN 时，`torch.manual_seed(3)` 后先初始化不同大小的 fc1，会改变后续参数的 RNG 位置；D0 与 D0+X 并没有保持共同隐藏层初始权重相同。这里由源码可以推导，本地没有 torch，未做数值初始化实测。

该初始化问题仅是后续需要多拟合种子控制的剩余风险，不能用它解释已经观察到的本轮排名或量化收益。

需要多拟合种子配对和有效随机公式/中性变换控制，区分公式归纳偏置与重初始化效果。先保留复现实验的原生模型为一套记录，新的稳定性评估可使用按层独立 RNG 或共享共同参数的初始化，所有组一致；这会改变比较实现，应新版本完整重跑基线，不能混用旧数值。

3 条轨迹只是同一划分上的 LLM 变化，replicate 号码不等于三个独立数据集，也没有 API generation seed 支持真正的共同随机数。KG—Agent 平均评分差 1.06 个百分点、诊断测试差 0.48 个百分点，很小；正式因果结论需要多个预先冻结的划分/拟合种子。当前数据已经用于开发，可继续做开发诊断，但论文必须有最终独立评估计划。

ANN 冻结公式转 HGB 后，KG 在全原始输入上收益最高，表明效益取决于预测器/输入和优化。这里所有新公式只是原生 14 输入的函数，未增加数据的信息；目标应表述为更好的归纳偏置、可执行假设和验证效率。不能认为有 KG 就应数学上严格占优。

## 六、模型问题与最小因果试验

换弱模型可能提高外部知识的相对价值，也可能增加领域误解与公式错误。现有实验没有跨模型因果证据。强模型已经能自行写出孔径/体积/惯量比，对这类 14 变量任务确实可能缩小外部知识的收益空间，但它不能解释 RAG 的零值失败为何更多。

当前 `run_jacs_au.py:360` 硬编码 GLM-5.3-Flash、thinking enabled、reasoning_effort low、temperature .2；仅改变配置文件不会改变模型/推理设置。模型能力、推理预算、采样温度应分别做受控设置，不能因为某次弱模型排序符合目标就选它作为主模型。

建议按顺序冻结，不一次性扩张：

1. **可执行性验证**：保留当前 3×3、同一 GLM/证据/预算，只给三组提供训练支持域与机器诊断修复；看每 27 假设的初始有效率、修复有效率、拟合有效数和收益。首先解决可证实失败，不以排名决定是否接受修复。
2. **证据组织消融**：固定来源事实和支持域修复，比较 no evidence、当前长 RAG、结构化短 RAG、相同事实平铺、图＋可执行变量约束。记同 token/调用/拟合成本，并另列质量优先的实际成本。
3. **能力依赖**：固定已经检查过的协议，在现模型与预先指定的较弱模型上完整比较 Agent/RAG/KG，不更改数据/预算/评估器。主要量为每个模型内部 RAG−Agent、KG−Agent 的增益，以及两模型之间这个差的变化。
4. **推理设置依赖**：在现模型上比较 low/.2 与官方推荐或更高推理设置，同样完整覆盖三组；这是推理设置消融，与“模型太新/太强”不同。和弱模型哪个先做可按 API 成本选择，必须在看到结果前冻结。

第一阶段最好先小规模检查支持域与定义工具确实纠正已知失败，再用新冻结划分或交叉评估检验预测收益。核心成功条件可以是 KG 相同预算下提高有效假设率和训练外误差、RAG 相对 blind 有可重复边际收益；排序是结果，不作为删去有效负结果或换基线的依据。
