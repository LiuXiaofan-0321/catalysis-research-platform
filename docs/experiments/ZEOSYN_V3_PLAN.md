# ZeoSyn V3 方案：从“公式再表达”转向“实体知识通道”

日期：2026-10-10。状态：**诊断 + 方案，未实施，未运行**。目标：KG > Agent > 公开 D0，且提升幅度大到足以支撑顶级期刊的主结论。

本文基于对整个框架（代码、提示词、五个评测集的历史、V1/V2 全部轨迹）的通读，以及一次用真实数据做的上限分析（`docs/experiments/zeosyn_v3_ceiling/REPORT.md`，脚本在 `scripts/diagnostics/zeosyn_ceiling/`）。上限分析用的是 60 棵树、2 个 seed、只对 43 列 D0 做插补的缩小设置，数字标注为“诊断值”，不是协议结果。

---

## 0. 结论先行

1. **五个评测集失败的根源相同，而且不是检索、提示词或 KG 质量，而是任务结构。** 从 Zeolite Atlas、AdsZeo、JACS Au 到 ZeoSyn V1/V2，任务都是“LLM 写一个由已有输入列组成的标量公式，拼进原模型”。树模型对输入的单调变换和比值几乎不敏感，这条通道的上限约 0.5 个百分点（诊断值：手工加 20 个凝胶比值 +0.52 pp；V1 Agent +0.54 pp；LLM-FE/CAAFE 类方法在强树模型上的文献典型值也是 0.5–2 pp）。任何知识源都不可能在 0.5 pp 的天花板下显示出优势。继续换评测集没有意义。

2. **要让知识显示优势，三件事必须同时成立，现在三件都不成立：**
   - **C1 信息**：KG 里有、训练集里没有、LLM 记不牢的信息。按论文划分时，KG 能补充新信息的测试配方只有 0.5%；凝胶化学规律是 LLM 的“头部知识”。
   - **C2 通道**：信息要以模型能用的形式进入。现在只能进一个标量；kg_* 特征只覆盖 12 个框架、没有 `Failed` 类、最常见框架用字母序编号。更致命的是（本次新发现）：**即使把一份完美的文献先验拼进 D0 重训 RF，提升也只有 +0.4 pp**，因为 14 项 OSDA 构象描述符在训练集里就是 OSDA 的身份证，树会走捷径记住“这个 OSDA → 这个框架”，而对新 OSDA 这些描述符毫无用处（1-NN 构象相似度对新 OSDA 的准确率只有 14%，低于全局众数的 25%）。
   - **C3 测量**：划分和指标要对那部分信息敏感。按论文划分 + 准确率，被已见 OSDA 和头部类别主导。

3. **新方案在真实数据上有量化的上限支撑。** 按 OSDA 留出（新 OSDA 场景），原生 RF 的 D0 从 43.6% 掉到 **29.0%**；用“同一 OSDA 在其他论文中的结果”做文献先验，与 RF 概率相乘，整体准确率达到 **40.1%**（只用结果分布）到 **42.8%**（用条件匹配的相近配方），覆盖配方上的 oracle 上限为 45–46%。也就是说，一个覆盖和质量接近 ZeoSyn 的合成记录 KG，可以在这个任务上带来 **+11 到 +14 个百分点**，而不是 0.5。

4. **现有 KG 达不到这个上限，必须重建为“专精合成记录 KG”。** 现有合成层只有 1,234 条链接到 OSDA 的记录、161 种 OSDA、每种中位 2 条、零凝胶组成，而且混进了催化剂制备、稳定性测试等非合成实验；在 OSDA 留出折上只覆盖 11–22 种留出 OSDA，覆盖配方上的众数准确率 27%，而 oracle 在同样配方上是 41%，有一折只有 5.9%（四丁基铵 → FAU，真值 MEL）。抽取 schema 本身是催化导向的（feed、WHSV），每篇最多 4 个实验，根本没有凝胶配比字段。

5. **KG > Agent > D0 的排序在这个设计下有机制保证，不靠运气。** Agent 的知识来自参数记忆，对头部 OSDA（TPA→MFI、TMAda→CHA）可靠，对长尾 OSDA 不可靠，这是 NLP 领域反复验证的规律（PopQA、Kandpal 2023、Head-to-Tail）；KG 组同时拥有记忆和检索。合并方式在开发折上调节信任权重，知识没用时自动退化为 D0，所以 Agent ≥ D0、KG ≥ Agent 几乎由构造保证；要成为“显著且大”的结论，只需 KG 的覆盖与质量达到 oracle 的大部分。

6. **代价**：重建 KG 的抽取是真正的工作量（约 3 周），其余代码改动约 1 周。LLM 调用量反而比 V2 少（每种 OSDA 一次调用，不再是每条轨迹 6 次）。

## 1. 五次失败的统一解剖

| 评测集 | 任务形式 | C1 信息 | C2 通道 | C3 测量 | 结果 |
|---|---|---|---|---|---|
| Zeolite Atlas | 从目录选描述符，Ridge | 无（目录内） | 单列 | 随机划分 | 探索性，无提升 |
| AdsZeo v1–v5 | 公式提名，自设 D0 | 无（与 D0 共线） | 单列 | 按拓扑划分 | 三组区间跨 0 |
| JACS Au V1–V5 | 14 列重组，ANN | 无（“新公式重表达 D0，不增加测量信息”——V5 自评） | 单列 | 随机划分 | 0.4–0.9%，KG−Agent 0.15 pp |
| ZeoSyn V1 | 43 列重组 + RDKit 量，RF | 无 | 单列 | 按论文划分 | Agent +0.54，KG +0.17 |
| ZeoSyn V2 | 同上 + kg_* 聚合特征 | 0.5% 的配方 | 标量 + 12 框架占比 | 按论文划分 | 全部跨 0；kg_* 使用率 0/120 |

共同点：**没有任何一次实验里，模型能接触到训练数据之外、且对预测目标有区分力的信息**。所谓“KG 条件”只是换了一批文字去刺激同一个公式生成器。V1 的结论“证据锁定话题、让提案同质化”是对的，但它是症状，不是病因——即使 V2 把检索做成了自主查询，所有组仍然只写凝胶比值（V2 开发集 120 个槽位，公式全部落在 OH/T、H2O/T、Si/(Al+P)、F 或阳离子电荷平衡四个家族里）。

### 1.1 为什么“公式通道”的天花板是 0.5 pp

- 诊断值：按论文划分，D0 43.6%；D0 + 20 个手工凝胶比值（Si/Al、H2O/Si、OH/Si、F/Si、OSDA/Si、Na/Si……）44.2%，**+0.52 pp**；macro-F1 +0.27 pp。
- 100 棵满深度的树用 `Si` 和 `OH` 两列的轴对齐切分就能逼近 `OH/Si`；`log(x)` 对树完全无效。V2 的冗余检查只拦截单列的严格单调变换，不拦截“树能自己学到的组合”。
- 这不是 ZeoSyn 独有：LLM-FE（TMLR 2026）在 19 个分类数据集上把 XGBoost 从 0.820 提到 0.840，在无污染数据集上只有 +0.0 到 +0.5 pp；OCTree 的绝对提升约 1–1.5 pp。我们的 Agent +0.54 pp 恰好是文献典型值，**说明实现没有问题，是任务没有空间**。

### 1.2 为什么 KG 的信息进不去（即使它是对的）

诊断：在 OSDA 留出划分下，用 ZeoSyn 自己模拟一个“完美文献 KG”（对每条测试配方，取同一 OSDA、来自其他论文的配方），得到一个 13 列的先验块（前 10 大类的先验概率、众数框架编号、支持数、熵），拼进 D0 重训 RF：

| 折 | D0 | D0 + 完美先验块 | 差值 |
|---|---:|---:|---:|
| 0 | 31.6 | 32.9 | +1.3 |
| 1 | 23.8 | 22.3 | −1.5 |
| 2 | 29.9 | 32.7 | +2.7 |
| 3 | 33.1 | 34.3 | +1.1 |
| 4 | 26.5 | 25.0 | −1.5 |
| 均值 | 29.0 | 29.4 | **+0.4** |

同一份先验，不重训、直接与 RF 概率相乘：**40.1%**（+11.1 pp）。

原因是训练阶段的捷径：训练行里 14 项 OSDA 构象描述符唯一标识 OSDA，树用它们把每个 OSDA 的配方切成纯节点，训练误差为零，先验列没有被“需要”；到了新 OSDA，构象描述符失去意义，用它们的树全部失效。这解释了 V2 的“只加文献特征 −0.03 pp”、以及新 OSDA 留出诊断里“D0 + 文献特征 ±2 pp”的结果——**不是 KG 没信号，是“拼进 D0 重训原生 RF”这个估计器结构性地无法奖励实体层面的知识**。

推论：V3 的评估估计器必须换成后验合并（RF 概率 × 知识先验，或在 OSDA 分组的袋外预测上做 stacking），同时仍以原生 RF 为预测主体。这不是放宽标准，而是修正一个会把真实效应抹成零的测量方法。

### 1.3 为什么按论文划分没有空间

- 诊断值（按论文划分，测试 4,405 条）：OSDA 在训练集里出现过的配方占 67%，RF 在这部分准确率 50.1%；OSDA 未出现过或无 OSDA 的配方，RF 只有 30.3%。差距全部在新 OSDA 上，但新 OSDA 配方只占测试集 12.7%，其中 KG 又有覆盖的只有 0.5%（24 条，1 种 OSDA）。
- 开发集里训练未见的 OSDA 配方 554 条，KG 覆盖的只有 17 条。
- 训练集本身就是比 KG 更好的“OSDA → 框架”查询表（开发集：训练集众数 40.0% vs KG 众数 30.6%）。

### 1.4 为什么现有 KG 不够

`data/kg_zeolite_v1` 的合成层是从催化导向的抽取结果里“顺手”筛出来的：

- 4,656 条记录，链接到 ZeoSyn OSDA 的 1,234 条，161 种 OSDA，每种中位 2 条，≥5 条的只有 35 种，≥20 条的 8 种；
- 凝胶组成：**0%**；晶化温度 78%（链接记录），时间 59%，产物 Si/Al 14%，氟/杂原子只是正则表达式旗标；
- 实验类型包括 `catalyst_synthesis`、`thermal_hydrothermal_stability_test`、`in situ 13C NMR`，产物字段只是“提到的框架”；
- 试剂链接把“出现在实验里的有机物”当成 OSDA：四丁基铵（17 条）→ FAU，真值 MEL；1,6-二氨基己烷 → -CLO，真值 TON；吡咯烷 → SOD，真值 FER；
- OSDA 留出折上（排除该折测试论文）：覆盖 47% 的配方但只有 11–22 种 OSDA；覆盖配方上众数准确率 27.3%，同样配方上 oracle 为 40.9%；真实框架出现在 KG 支持集中的比例只有 44%；
- 抽取 prompt 的 schema（`literature_pipeline/prompts/data-v2.txt`）每篇最多 4 个实验，条件字段是 temperature / pressure / feed / WHSV / GHSV，没有凝胶配比；KG 里也没有失败/无定形结果，而 `Failed` 是最大的类（24.6%）。

结论：这个 KG 作为合成知识源，弱于 ZeoSyn 训练集本身。它是一个很好的催化证据图，但不是这个任务需要的知识。

### 1.5 轨迹取证：V2 开发集 120 个槽位逐条核对的结果

完整报告：`docs/experiments/zeosyn_v2_forensics/REPORT.md`（KG 证据按哈希逐条重建，60/60 一致；D0 评分逐位复现；90 个不同公式各自单独重新评分，5 个官方 seed）。超出上文的新事实：

1. **现有 KG 在按论文划分下的理论上限只有 +1.6 pp。** KG 众数框架等于真值的 1,840 条覆盖配方里有 563 条（30.6%），而 D0 在这 563 条上本来就有 90% 正确；D0 错、KG 对的只有每 seed 56 条，反过来 KG 会覆盖掉 519 条 D0 已经答对的。所以即使模型完美使用了 kg_* 特征，也不可能超过 +1.6 pp。
2. **打乱 KG 在所有指标上与真实 KG 不可区分**：引用证据的槽位 23 vs 19，轨迹均值 +0.07 vs +0.00，只加特征 +0.34 vs −0.03，RF 对 kg_* 列的总重要度 13.4% vs 14.6%（最重要的 kg_* 列排第 26 位，是 `n_experiments`）。RF 把 kg_* 当成 OSDA 指纹在用，对内容无感；通过提示词和特征两条通道都没有传递任何知识。
3. **组别与输出无关。** 120 个槽位里 75% 落在 OH/T、H2O/T、Si/(Al+P) 三个家族；15 个公式字符串跨组重复；kg 第 7 条轨迹与 rag 第 5 条逐公式相同、分数相同。V2 的改造确实改变了知识组的输出，但只是把它们改成了 V1 Agent 本来就写的东西（三大家族占比：V1 的 Agent/RAG/KG 为 17/5/2 of 30，V2 四组为 18/25/23/24）。V1 的话题锁定被去掉后，换上的是模型自己的先验，而四个组的先验是同一个。
4. **KG 事实唯一能接到公式输入上的钩子是 F、杂原子和温度**，所以证据对公式的全部可见影响就是 3 个 F/T 和 1 个 Ge 分数，单独评分 +0.43 / −0.07 / −0.17 / −0.10 pp；其余引用都是“与证据一致”式的装饰。KG 证据平均只用 231 个 token（RAG 用满 2,932），知识组的推理 token 反而更少（466–497 vs Agent 650）。
5. **单个描述符能到 +0.5 到 +0.9 pp，但三个叠在一起不行。** 90 个公式单独评分均值 +0.18，9 个超过 +0.5（其中 5 个来自打乱 KG 组）；可任何轨迹都没超过 +1.02，四组的平衡准确率都掉 0.6–0.75 pp：比值特征把 RF 推向多数类，第二、第三个描述符通常抵消第一个（打乱 KG 第 5 条轨迹单个 +0.87，整条 +0.06）。最常被提出的 `OH/(Si+1e-6)`（6 个槽位、3 个组）单独是 −0.25 pp。
6. **设计的分辨率不够。** 轨迹标准差 0.27–0.40 pp，D0 自身 seed 标准差 0.60 pp，单条轨迹内 seed 间摆动可达 ±1.9 pp；要检出 0.19 pp 的组间差，每组需要 50 条以上轨迹。
7. 数据结构本身让几类公式失效：F 与 OH 从不共存，所有 F-vs-OH 描述符退化为 F 的单调函数；AlPO 配方（Si = 0，占 16%）让 OH/Si 类比值退化。HGB 灵敏度分析退化为常数预测器（准确率 = 多数类占比 23.5%），没有第二模型的交叉检验。

这些事实共同说明：在按论文划分、OSDA 级聚合事实、只能写凝胶比值公式的设置下，H2（KG > Agent）不是被证伪了，而是**不可检验**。V3 的三项改动（OSDA 留出、实体档案通道、RF × 先验合并）各对应其中一条。

## 2. V3 任务定义

### 2.1 核心任务：新 OSDA 的产物相预测

> 给定一条使用 OSDA *o* 的合成配方，而 *o* 从未出现在训练数据中，预测主产物框架。

这是真实场景（任何实验室的数据库都只覆盖文献的一部分；ZeoSyn 的 746 种 OSDA 里 448 种只在一篇论文中出现），是 ZeoSyn 原作者在后续工作（DiffSyn，Nat. Comput. Sci. 2026）中采用的划分方式（按“框架–OSDA 体系”留出并单列严格 OOD 子集），也是文献知识唯一有可能超过数据集本身的地方。

- **划分**：按 OSDA1 的 InChIKey 做 GroupKFold，5 折，shuffle 种子 1；无 OSDA 的配方（2,627 条）始终留在训练集。每折留出 149–150 种 OSDA、2,564–4,956 条配方。
- **开发折 / 测试折**：折 0、1 用于开发（最多 3 轮迭代），折 2、3、4 冻结后只评估一次。
- **D0**：不变——原论文 43 列、原生 `RandomForestClassifier(n_estimators=100)`、原生 IterativeImputer（只在训练行拟合）。诊断值：D0 准确率 29.0%（23.8–33.1），平衡准确率 10.7%，macro-F1 10.5%。
- **主指标**：准确率（与原论文和 V1/V2 一致）；次指标：macro-F1、top-3 准确率、**按 OSDA 平均的准确率**（每种留出 OSDA 一个数，防止被 TEA 的 1,866 条配方主导）。
- **统计单位**：留出 OSDA（三个测试折约 450 种，其中有 ≥2 条配方的约 360 种），配对差值的 bootstrap 区间。V1/V2 用 10 条轨迹作统计单位，功效太低；这里一次运行就有几百个独立单位。
- **次要划分（敏感性）**：(a) OSDA 簇留出：按 Morgan 指纹 Butina 聚类（阈值 0.6），整簇留出，检验同系物泄漏；(b) 时间前向：≤2018 训练、2019–2021 测试（1,532 条，344 篇，其中 15.5% 的 OSDA 配方用的是 2019 年前未报道过的 OSDA）。(c) 原按论文划分继续报告，作为“分布内无空间”的对照——这本身是论文的一个发现。

### 2.2 为什么这个划分对 KG 是公平的、对审稿人是可辩护的

- 留出 OSDA 后，训练集不含该 OSDA 的任何配方，RF 只能靠凝胶组成和对新 OSDA 无效的构象描述符（1-NN 构象相似度 14%）。
- KG 排除**配方自己所在的论文**（直接答案泄漏），保留其他论文的结果——这正是“文献知道、数据集不知道”的定义。Agent 的参数记忆同样来自这些文献，所以 KG vs Agent 的比较不受此影响。
- 预注册两个更严格的变体：**external-only**（KG 排除全部 ZeoSyn 论文，只剩非 ZeoSyn 文献；现有合成层里 53% 的链接记录来自非 ZeoSyn 论文）和**时间截断**（只用早于该配方论文的文献）。主分析用“排除本文”，两个变体作为敏感性分析报告。
- 最终的防泄漏证据是 **前瞻集**（§5.6）：2025–2026 年发表、KG 语料和 LLM 训练截止之后的合成论文。

### 2.3 文献知识在这个任务上的上限（诊断值）

“完美 KG” = 对每条测试配方，取同一折里 OSDA 相同、但来自**其他论文**的 ZeoSyn 配方（ZeoSyn 是人工整理的，相当于一个抽取无误、链接无误、带完整凝胶组成的文献 KG）。凝胶空间 = 27 列凝胶摩尔分数按训练行标准化后的欧氏距离。5 折均值：

| 预测方式 | 覆盖配方上准确率 | 覆盖率 | 整体准确率（未覆盖处用 D0） |
|---|---:|---:|---:|
| RF D0（参照） | 27.1 | — | 29.0 |
| 全局众数（Failed） | — | — | 24.7 |
| 1-NN OSDA 构象描述符 | — | — | 14.1 |
| 文献众数框架 | 38.5 | 84.1% | 38.8 |
| 条件匹配最近配方（凝胶空间 1-NN） | 45.2 | 84.1% | 44.4 |
| 条件匹配最近配方（凝胶 27 列 + 晶化时间、温度） | 46.2 | 84.1% | 45.3 |
| RF 概率 × 文献分布先验（ε = 0.01） | 40.0 | — | 40.1 |
| RF 概率 × 条件匹配 5-NN 先验 | 43.2 | — | 42.8 |
| RF 重训于 D0 + 先验块（§1.2） | — | — | 29.4 |

三个要点：

1. **可达增益 +11 到 +16 pp**，不是 0.5。即便只达到上限的 70%，也是 +8 pp 以上，是文献中 LLM 特征工程方法的 10 倍。
2. **条件化比众数多 6–7 pp**。“TEA 得到什么”几乎没有信息（1,866 条配方、43 种框架、众数 *BEA 只占 24.9%）；“TEA 在 F⁻ 介质、Si/Al > 50 得到什么”才有信息。所以 KG 必须有凝胶条件，这是重建 KG 的核心要求。
3. **合并方式决定成败**：同一份先验，相乘 +11 pp，拼进 RF +0.4 pp。

此外，OSDA 的头部效应很强：按折看，TPA 占主导的第 4 折 oracle 可达 52–55%，TEA 占主导的第 1 折只有 45%。所以必须按 OSDA 平均来报告，并按 OSDA 流行度分层。

## 3. 知识通道：从“标量公式”到“实体合成档案”

### 3.1 描述符的新定义

V3 保留“LLM 提出可计算、可验证的描述符 X，比较 D0 与 D0 + X”这条主线，但 X 的定义从一个标量公式升级为**实体级知识向量**：

对每种 OSDA *o*（InChIKey 标识），生成一份结构化的**合成档案** J(*o*)：

```json
{
  "osda": {"inchikey": "...", "names": ["tetraethylammonium", "TEA"], "smiles": "..."},
  "reported_outcomes": [
    {"framework": "*BEA", "n_reports": 54, "n_papers": 31,
     "conditions": {"mineralizer": "OH", "si_al": [10, 100], "heteroatoms": [], "temp_c": [135, 150], "cations": ["Na"]},
     "evidence": ["rec-0a12", "rec-77f3"]},
    {"framework": "CHA", "n_reports": 17, "n_papers": 9,
     "conditions": {"mineralizer": "F", "si_al": [15, 50], "heteroatoms": ["B"], "temp_c": [150, 175]},
     "evidence": ["rec-1b90"]},
    {"framework": "Failed", "n_reports": 20, "conditions": {"temp_c": [100, 130]}, "evidence": ["rec-2c01"]}
  ],
  "analog_osdas": [{"inchikey": "...", "name": "tetrapropylammonium", "weight": 0.3, "why": "same quaternary ammonium, larger alkyl"}],
  "confidence": 0.8,
  "knowledge_source": "kg | prior_knowledge | both"
}
```

一个**确定性的编译器** φ(*o*, *x*) 把档案和配方的实际条件 *x*（是否含 F、Si/Al 分箱、杂原子、温度）变成特征向量：对每个框架类别（训练集出现的框架 + `Failed` + `other`）给出按条件匹配度加权的先验概率 p_J(y | *o*, *x*)、总支持数、论文数、熵、是否被覆盖、类比 OSDA 的加权先验。这个向量就是 X。

### 3.2 三个实验组的唯一差别：档案从哪里来

| 组 | J(*o*) 的来源 | LLM 的任务 |
|---|---|---|
| **Agent** | 参数记忆 | 给出 OSDA 名称、同义词、SMILES，要求列出“据你所知该 OSDA 被报道合成过哪些框架、在什么条件下”，并给置信度；不提供任何检索 |
| **KG** | 合成记录 KG（§4）：按 InChIKey 精确检索该 OSDA 的全部记录（排除本文），再加结构相似 OSDA（Tanimoto ≥ 0.6）的记录和框架侧事实 | 把检索到的记录汇总成档案，每条 `reported_outcomes` 必须引用记录 ID；对未覆盖的 OSDA 做结构类比，写明理由 |
| **KG-direct**（对照） | 同一批记录，不经 LLM，规则汇总 | 无 LLM；衡量 LLM 在 KG 之上的增量 |
| **RAG**（辅助） | 同预算的文本片段 | 同 KG 组，但只有片段 |
| **打乱 KG**（对照） | OSDA–记录对应关系打乱 | 同 KG 组 |

LLM 调用数：每种留出 OSDA 一次（每折约 150 次），5 折 × 3 组约 2,250 次，远少于 V2（4 组 × 10 轨迹 × 3 轮 × 2 步 = 240 次调用但每次都带 3,000 token 证据，而且统计功效极低）。训练 OSDA 不需要档案（见 3.3）。

### 3.3 评估估计器：原生 RF × 知识先验

主分析：

p(y | *x*, *o*) ∝ p_RF(y | *x*) · (p_J(y | *o*, *x*) + ε)^α

- p_RF 是原生 RF（D0、100 棵树、5 个 seed）在该折的预测概率，与 D0 完全相同；
- α、ε 在开发折上按组各自选定（网格 α ∈ {0, 0.25, 0.5, 1, 2}，ε ∈ {0.01, 0.05, 0.2}），测试折冻结。α = 0 时退化为 D0，所以任何组都不会显著低于 D0；知识越准，开发折选出的 α 越大；
- D0 的报告值就是 α = 0 的结果，与原生 RF 完全一致。

次分析（预注册）：(a) stacking——在训练 OSDA 上做 OSDA 分组的袋外 RF 预测，用 [log p_RF, log p_J, 支持数, 熵] 训练一个多分类逻辑回归，在测试折应用；(b) “拼进 D0 重训 RF”继续报告，作为 §1.2 结论的实证。

关于 V2 已有的标量公式通道：保留为可选的第二通道（LLM 仍可提一个公式），但不再作为主结果，也不再是“知识是否有用”的裁判。

### 3.4 为什么这个设计里 KG > Agent > D0 有机制保证

- **Agent vs D0**：对 TPA、TMAda、TEA、HMI、18-crown-6 这类 OSDA，任何 LLM 都知道它们导向什么；这些 OSDA 占了测试配方的大头（前 20 种 OSDA 占 44% 的配方）。α 在开发折上调好后，Agent 组在这些配方上大幅超过 D0，在长尾 OSDA 上退化为 D0。
- **KG vs Agent**：差别出现在长尾。ZeoSyn 有 746 种 OSDA，346 种少于 5 条配方；LLM 对它们的“回忆”大多是幻觉（Kandpal 2023：问答准确率随预训练语料中实体出现次数单调下降；Mallen 2023：检索增强的收益集中在长尾实体）。KG 组对这些 OSDA 有记录就赢。
- **要成为“大而显著”的结论**，KG 的覆盖与质量要接近 oracle：留出 OSDA 中有 ≥3 条非本文记录的比例 ≥ 50%（现在 11–22 种 / 150 种），覆盖配方上的众数准确率 ≥ 0.85 × oracle（现在 0.67 ×）。这就是重建 KG 的目标，也是关卡。

### 3.5 机制分析（预先指定）

1. 按 OSDA 在 KG 中的记录数分层（0、1–2、3–9、≥10）：KG − Agent 的差值应随记录数增加，Agent − D0 应随 OSDA 的文献流行度增加。
2. **LLM 记忆审计**：对每种留出 OSDA，把 Agent 档案里声称的框架与 ZeoSyn 真值比较，得到“回忆准确率 vs 流行度”曲线——这是论文的机制图，直接对应 long-tail 文献。
3. 按条件分层：含 F / 无 F、含杂原子 / 无、Si/Al 分箱，验证“条件化记录”比“众数”多出来的部分来自哪里。
4. `Failed` 类：KG 是否能预测失败（现有 KG 没有失败记录，V3 必须抽取）。
5. 竞争相：2,711 条配方记录了次相（Code2），常见竞争对（TON/MFI、FAU/GIS、AFI/CHA、*BEA/MTW）上，知识先验是否能把 top-1 判对、把竞争相排在 top-2——这是 ZeoSyn 原文强调的科学问题。

## 4. 专精 KG：ZeoSyn-KG v2（合成记录图）

这是方案的核心工作量，也是“KG 可以是专精的”这句话的落地。

### 4.1 抽取目标

每条合成实验一个记录，schema `zeolite_synthesis_record.v1`：

| 字段 | 说明 | 为什么必须 |
|---|---|---|
| OSDA（可多个） | 原文名称、缩写、SMILES/InChIKey（OPSIN 离线解析，复用现有缓存） | 实体链接 |
| 凝胶组成 | 以 Si（或 T 原子）归一的摩尔比：Al、P、B、Ge、Ti、Ga、Zn、Sn、Na、K、Li、Cs、F、OH、H₂O、OSDA；原文如写 SiO₂/Al₂O₃ 等氧化物比，保留原始写法并换算 | 条件化先验（§2.3 多出的 6–7 pp） |
| 矿化剂 | OH / F / 两者 | 相选择性的首要开关 |
| 晶种 | 有/无、晶种框架 | ZeoSyn 有 5,936 条带晶种，但 D0 不含它 |
| 温度、时间、静态/旋转 | 数值 + 单位 | 已有 |
| 产物 | 主相（IZA 代码或材料名 → 代码）、次相、**无定形 / 致密相 / 未结晶 → Failed** | KG 现在没有失败记录，而 Failed 占 24.6% |
| 产物 Si/Al、结晶度 | 可选 | 次要 |
| 来源 | DOI、年份、页码、原文引用、表格行号 | 排除本文、时间截断、审计 |

抽取对象是**合成表的每一行**（主文 + SI），不再是“每篇最多 4 个中心实验”。提示词按表格行抽取，并要求把“SDA / template / structure-directing agent”明确标注的试剂才记为 OSDA（解决四丁基铵→FAU 一类错误）。

### 4.2 语料

1. 现有 6,691 篇分子筛论文（PDF 已在服务器）；
2. **新增 2022–2026 年的分子筛合成论文**（文献流水线已有采集与结构化能力）：这既扩大长尾覆盖，又是前瞻集（§5.6）的来源；
3. 可选的第二层（对应原研究问题里的 Medium KG）：OSDB（zeodb.mit.edu，112,426 个 OSDA–框架复合物的结合能/竞争能；2026-10-10 访问时站点 503，需另行获取）或 ZeoBind 预测的亲和力矩阵，以及 IZA 框架描述符（环尺寸、通道维数、最大包含球）。它们为 KG 未覆盖的全新 OSDA 提供物理先验，是 LLM 记忆完全没有的信息。

### 4.3 质量门（关卡 B）

ZeoSyn 本身就是人工整理的金标准，与 KG 语料重叠的论文至少 762 篇。在 300 篇试点（含 100 篇重叠论文）上：

- (OSDA, 主产物) 与 ZeoSyn 一致率 ≥ 85%；
- 凝胶比抽取：有凝胶组成的记录比例 ≥ 60%，与 ZeoSyn 的 Si/Al、H₂O/Si 相对误差中位数 ≤ 10%；
- OSDA 链接：100 条人工抽查精度 ≥ 90%；
- Failed 记录比例 ≥ 10%（否则说明抽取漏掉了失败实验）。

ZSEE（arXiv 2512.15312）报告 LLM 对分子筛合成事件的论元抽取 F1 只有 50–65%，所以这一关不能跳过；达不到就改提示词和后处理，而不是带着噪声往下走。

### 4.4 覆盖门（关卡 C）

全量抽取后，在 OSDA 留出的 5 折上统计（排除本文）：

- 留出 OSDA 中有 ≥3 条非本文记录的比例 ≥ 50%（现有 KG：有任何记录的只有 7–15%，即每折 11–22 种 / 150 种）；
- 覆盖配方上的众数准确率 ≥ 0.85 × oracle（现有 0.67 ×）；
- 真实框架出现在 KG 支持集中的比例 ≥ 70%（现有 44%）。

达不到覆盖门，KG 组的提升就会被覆盖率稀释，此时应如实报告并把 external-only 的局限写进论文，而不是继续调提示词。

### 4.5 实体链接与检索

- OSDA：InChIKey（最大有机片段、去电荷、去立体），复用 V2 的 OPSIN/PubChem 缓存与别名表；
- 框架：现有 128 码词表 + 材料名映射（SSZ-13 → CHA 等）；增加 Failed 词表（amorphous、dense、quartz、no crystalline product、unidentified）；
- 检索：按 InChIKey 精确命中 → 结构相似 OSDA（Morgan 指纹 Tanimoto ≥ 0.6，RDKit 已在台式机环境）→ 框架侧事实；返回结构化记录而不是句子片段；
- 排除规则与 V2 一致（本文 DOI 排除；评估论文排除；fail-closed 检查），无 DOI 的记录一律不用于先验。

## 5. 实验协议（预注册要点）

### 5.1 假设

- **H1**：Agent > D0（Agent − D0 的 95% 区间下限 > 0，单位：留出 OSDA）。
- **H2（主）**：KG > Agent（同上）。
- **H3**：KG − KG-direct（LLM 在 KG 之上的增量），只报告区间。
- **H4**：KG > 打乱 KG，KG > RAG，只报告。
- 幅度预期（写进预注册，作为判断“大”的标准）：KG − D0 ≥ +8 pp（按配方）且 ≥ +5 pp（按 OSDA 平均）。

### 5.2 固定项

- 模型 GLM-5.3-Flash，thinking 开启，temperature 0.2，每种 OSDA 一次调用，输出 JSON 档案，格式修复最多 1 次，失败的 OSDA 记为未覆盖（不补抽）。
- D0、RF、插补、seed 与 V1/V2 相同。
- α、ε 在开发折 {0, 1} 上选定，写入配置后冻结；测试折 {2, 3, 4} 各评估一次。
- 全部留出 OSDA 计入分母，包括 LLM 调用失败和档案为空的。

### 5.3 防泄漏

- KG：排除本文 DOI（主）；external-only 与时间截断（敏感性）；无 DOI 记录不用。
- LLM：Agent 档案无法排除记忆，这会**高估 Agent**、低估 KG − Agent，方向上保守；补充 tabmemcheck 式审计（让模型补全 ZeoSyn 行、按 DOI 复述配方），在论文中披露。
- 直接答案审计：对每个测试折报告“KG 众数框架 = 真值”的比例，并与 D0 对比（这个数现在是 27% vs D0 27%，重建后应明显高于 D0）。

### 5.4 开发流程

开发折上最多 3 轮迭代，每轮记入开发日志（改了什么、为什么、看到了什么）。关卡 D：最后一轮开发折上 KG − Agent 的区间下限 ≤ 0，就不进测试折，如实报告。

### 5.5 必须加的无知识基线（投稿需要）

- D0 + 类别先验校准（RF 概率 × 训练集类频率^β）；
- D0 + 构象相似度先验（1-NN / k-NN 在 OSDA 描述符空间的训练 OSDA 结果分布）——诊断值 14%，预期很弱，但审稿人会问；
- CAAFE / LLM-FE 风格的无知识 LLM 特征工程，预算与 Agent 组相同。

### 5.6 前瞻集（顶刊级证据的关键）

从 2025–2026 年新发表的分子筛合成论文（KG 语料截止与 GLM 训练截止之后）人工整理 200–400 条配方，优先包含 ZeoSyn 中没有的 OSDA。KG 语料只用 2024 年及以前的论文。这是唯一能同时排除 KG 泄漏和 LLM 记忆泄漏的测试，也是 DiffSyn、ZeoBind 这类工作被接受的共同模式（系统级划分 + 严格 OOD 子集 + 前瞻验证）。如果课题组有合成条件，再做一次“预测新 OSDA–框架配对并合成验证”，就是 Nature 子刊级别的闭环；没有也不影响方法学主结论。

## 7. 对研究问题的修订建议

原问题是“知识范围从本领域到邻近、跨领域扩展时，提出可验证描述符的能力是否提高”。五次实验表明，在“再表达 D0”的任务上这个问题无法被任何数据回答。建议改写为**知识类型与粒度的 scaling**：

| 层级 | 内容 | 预期（诊断值） |
|---|---|---|
| L0 | OSDA → 框架的边际事实（现有 KG 的形态） | 众数先验：覆盖处 38.5% |
| L1 | 条件化合成记录（V3 的 Small KG） | 条件匹配：45–46%，比 L0 多 6–7 pp |
| L2 | + 计算的 OSDA–框架亲和力、框架结构描述符（Medium） | 对 KG 未覆盖的全新 OSDA 起作用；量待测 |
| L3 | + 邻近/跨领域文献（Large） | 对该任务预期 ≈ 0；如实报告即是结论 |

这把“Small / Medium / Large”从论文数量和领域广度改成了信息粒度，每一层都有可测的差值，而且 L0 → L1 的跳跃已经在数据上看到了。原 RQ1–RQ7 中，RQ1（KG 是否优于 LLM-only）、RQ5（OOD 增益）、RQ6（strengthen / revise 已有结论——竞争相分析）直接对应 V3 的 H2、主划分和 §3.5 第 5 项。

## 8. 风险与诚实声明

- **最大风险是抽取质量。** 关卡 B 不过就不要往下走。ZeoSyn 作为金标准可以把这个风险量化，而不是靠感觉。
- **Agent 可能很强。** GLM 对 ZeoSyn 源论文甚至数据集本身可能有记忆。这会缩小 KG − Agent，但不会制造假阳性；如果 KG − Agent 在尾部仍为正而头部为零，也是一个清晰、可发表的机制结论。
- **external-only 变体的覆盖率会明显低于主分析。** 应在论文中并列报告，不选择性呈现。
- **效应集中在头部 OSDA 的折（如 TPA 所在折）会拉高按配方的均值。** 按 OSDA 平均的指标必须同时报告。
- 本文的全部“诊断值”来自 60 棵树、2 个 seed、只插补 D0 列的缩小设置，与正式协议（100 棵树、5 个 seed、全列插补）会有零点几个百分点的差别，但不会改变任何结论的方向。
