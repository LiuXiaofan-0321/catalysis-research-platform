# 科学假设发现：阶段成果与后续研究路线

更新时间：2026-09-27。

本文汇总当前已完成的研究工作、结果的解释范围，以及讨论形成的后续路线。实验数据截至已归档的 2026-09-24 批次；本文整理时未重新提交服务器作业。后文的轮数扩展、multi-agent、Jev 和新增实验均为待实施方案。

## 1. 当前判断与研究目标

现有 demo 已跑通“文献证据 → 假设与公式 → 计算验证 → 反馈 → 下一轮”的最小闭环。开放生成的部分公式能够降低当前评分集上的预测误差，因此具备继续研究的基础。

现阶段尚不能认定 KG 稳定优于 RAG 或 Agent，也不能把预测分数改善直接解释为发现了新的科学机制。下一步应研究迭代为什么有效、协作是否改善假设、以及如何分配验证预算。

两条研究线的目标如下：

| 研究线 | 核心问题 | 需要积累的证据 |
| --- | --- | --- |
| NCS／NMI 科学主线 | 模型能力、知识范围、知识结构如何影响可验证的科学假设发现？ | 证据与机制对应、描述符的物理意义、跨任务或跨体系有效性、独立计算或实验验证 |
| Agent／harness 会议分支 | 如何利用反馈、角色分工和判断模型，在有限预算下更有效地探索科学假设？ | 同预算基线、闭环收益、成本、失败分析、误拒绝有益候选的风险、跨任务迁移 |

NCS／NMI 与 A/B 类会议是投稿目标，当前 demo 不代表已经达到对应发表要求。工具和数据处理可以共用，两条线需要分别建立明确的贡献和证据，并在发表时交代已有成果。

## 3. 从“菜单选择”到“开放提出公式”的变化

| 阶段 | 候选来源 | 模型承担的工作 | 可以研究的问题 |
| --- | --- | --- | --- |
| 早期 TheMeCat / AdsZeo v1–v4 | 人工预定义的描述符目录 | 选择描述符、说明理由、根据反馈调整选择 | 知识能否帮助选择已有描述符 |
| 当前 AdsZeo v5 | 模型根据可用变量自主写出表达式 | 提出假设和候选公式，根据执行与评分反馈修订 | 知识与反馈能否帮助构造有用的描述符 |

当前运行入口启用了 `--open-nomination --score-only`。虽然入口文件仍叫 `run_glm_adszeo_v2.py`，实际调用的是 v5 的 `run_adszeo_nomination_loop`。

当前循环为：

```text
D0
  → 第 1 轮：提出 3 个候选，逐一评估，最多保留 1 个有益公式 X
  → 第 2 轮：读取反馈，在 D0 + X 上提出 3 个新候选，最多保留 Y
  → 第 3 轮：读取反馈，在 D0 + X + Y 上提出 3 个新候选，最多保留 Z
  → 输出最终集合；某轮没有正收益则保持已有集合
```

每个候选均与“D0 + 之前保留的公式”比较。同一轮的三个候选不会自动全部加入，最终最多增加三个描述符。

当前 schema 每轮包含一个总体 `hypothesis`，以及三个分别带有 `rationale`、`expected_direction`、`falsification_criteria` 的公式候选。因而“每轮三个公式”尚不等于“三个独立、完整的机制假设”。后续如果研究竞争机制，应建立每个假设与公式、证据、验证动作的明确对应。

实际输出已包含“Al 比例 × 环结构熵”等组合表达式，也存在直接使用已有输入或数学上相近的提议。开放生成说明候选没有被固定目录穷尽；是否具有科学新意仍需审查，不能用公式字符串不同来证明。

## 4. 已完成实验及结果

### 4.1 当前采用的评分规则

按讨论确定的方案，当前 v5 使用一个自适应评分集：

- 训练部分继续用于拟合预测模型。
- 原验证部分作为唯一评分集，参与每轮选择和最终改善计算。
- 原独立测试部分不参与当前批次的结果计算。
- 只保留使当前评分 MAE 严格降低的公式；没有改善时保留原集合。

改善率为 `(D0 的评分 MAE − 最终评分 MAE) / D0 的评分 MAE × 100%`。

该规则保证累计评分改善不为负，但不保证严格为正，也不保证三种知识条件的排序。正改善说明在这组固定评分数据上找到了更优集合；它不等同于未见材料或未见拓扑上的泛化收益。

### 4.2 最新批次：3741576

模型为 `glm-5.3-flash`，三种知识条件各 10 次重复，每次三轮、每轮三个公式；30 条轨迹全部完成。D0 的评分集拓扑 macro-MAE 为 0.289152 mol/kg。

| 模式 | 最终评分 MAE 均值（mol/kg） | 相对 D0 改善均值 | 正向次数 |
| --- | ---: | ---: | ---: |
| Agent | 0.272236 | +5.85% | 10/10 |
| RAG+Agent | 0.271122 | +6.24% | 10/10 |
| Small KG+RAG+Agent | 0.267470 | +7.50% | 10/10 |

本批均值符合 `KG+RAG > RAG > Agent`，但完整排序仅出现 3/10 次，KG+RAG 超过 RAG 为 6/10 次。因此这是积极的探索性结果，尚不足以断言稳定优势。

### 4.3 跨批次稳定性

前一个修正批次 `3741200` 的公式选择过程使用相同评分逻辑，独立测试发生在选择结束后。因此，可取该批的验证反馈分数与最新批次的评分结果做探索性汇总；不能把它的独立测试分数直接混入。

| 批次：评分集改善均值 | Agent | RAG+Agent | KG+RAG+Agent |
| --- | ---: | ---: | ---: |
| 修正批次 3741200，各 10 次 | +8.26% | +6.69% | +6.57% |
| 单评分集批次 3741576，各 10 次 | +5.85% | +6.24% | +7.50% |
| 两批合计，各 20 次 | +7.06% | +6.46% | +7.04% |

合计后 KG+RAG 与 Agent 基本持平，知识条件的排序会随批次改变。重复使用同一个任务和拓扑划分，主要反映生成随机性，不代表跨数据集的不确定性。

### 4.4 保留的历史结果与修复记录

修正批次 `3741200` 曾报告独立测试改善：Agent −1.96%、RAG +0.25%、KG+RAG −0.21%。这说明在评分集上选择的公式未必能改善未见拓扑。它与当前单评分集指标回答不同问题，均保留记录。

更早批次 `3739217` 存在检索证据编号处理错误：引文中的空行触发整段上下文重复。问题已修复，修正后批次采用新的证据分段逻辑。该故障批次以及受同一问题影响的旧版知识模式排序不能用于公平比较；旧报告已标记局限。

### 4.5 候选质量与 harness 的研究切入点

对两个修正批次的原始执行反馈统计如下：

| 项目 | 3741200 | 3741576 | 合计 |
| --- | ---: | ---: | ---: |
| 提议公式数 | 270 | 270 | 540 |
| 未通过执行或质量检查 | 61 | 59 | 120 |
| 进入下游预测评估 | 209 | 211 | 420 |
| 相对当前集合有正边际收益 | 107 | 107 | 214 |
| 相对当前集合没有正边际收益 | 102 | 104 | 206 |

统计口径：`status == executed` 表示进入评估；`marginal_validation_delta_macro_mae < -1e-12` 表示正边际收益。收益取决于当轮已有集合；未被保留不一定无益，因为每轮只选最优的一个。

420 个已评估候选中约 49% 没有当轮边际收益，为研究候选决策提供了动机，但尚不能证明这些候选可以被提前准确识别。120 个执行失败已由程序检查拦截，不能把它们全部计为未来 Jev 新增的节省。540 个提议来自同一任务的 60 条相关搜索轨迹，不是 540 个独立科学任务。

## 6. 第一阶段：假设轮数与反馈价值

### 6.1 研究问题

1. 收益在哪一轮趋于饱和，不同知识条件是否不同？
2. 后续提议是否利用了失败原因和已保留公式，还是在重复近似表达式？
3. 相同预算下，反馈驱动的多轮生成是否优于缺少反馈的搜索？

### 6.2 建议实验

先扩展至 1、3、5、8 轮，每轮三个候选。当前代码把轮数固定为三轮，实施前需要将轮数、候选数和最终保留上限显式配置化，并保留现有三轮设置作为基线。

将实验区分为两个问题：

- **轮数扩展曲线：**观察更多轮数及其追加成本带来的改善，记录实际保留数。这是规模增长实验，不能据此单独声称迭代策略优越。
- **反馈与调度对照：**控制总提议数、评估预算和最终特征数上限，对比完整反馈、只传已保留集合、去掉评估反馈等条件；再设计一次性生成候选的对照。一次性候选也应使用一致的保留和评分政策，并完整计入筛选成本。

每轮记录：当前最佳 MAE、边际收益、执行成功率、近似重复率、机制类别、失败类型、模型调用成本、检索耗时、拟合耗时与端到端耗时。公式去重应考虑交换顺序、代数等价和数值冗余。

累计评分非下降由保留规则保证。研究重点是相同预算下的增益、达到目标分数的成本，以及反馈是否提高了后续提议质量。

### 6.3 阶段产出

- 一份轮数—收益—成本报告。
- 反馈是否有效、在哪些模式下有效的结论。
- 主要失败类别与重复模式，为 multi-agent 分工提供依据。
- 建议轮数或停止策略；停止规则先在开发任务上确定，再评价其损失与节省。

## 7. 第二阶段：multi-agent 与完整工具链

### 7.1 最小分工方案

| 角色或模块 | 职责 | 输出 |
| --- | --- | --- |
| 假设 Agent | 根据证据与反馈提出机制、表达式和可检验预测 | 候选假设、公式、适用条件、证据引用 |
| 质疑 Agent | 寻找反例，检查解释与公式的一致性，发现缺失证据 | 明确的质疑、修订建议、检索需求或验证动作 |
| 工具执行与调度模块 | 调用检索、检查表达式、执行下游模型、保存状态、组织下一轮 | 实测结果、失败原因、完整轨迹 |

数学运算、语法检查、MAE 和保留决策由程序完成。完整工具链还需要统一状态、工具输入输出、失败恢复和结果追踪，不能仅靠增加 Agent 数量实现。

建议为每条候选建立稳定的 hypothesis ID，使证据、公式、质疑、修订和执行结果可以串联；科学解释和计算结果分别保存，避免用 Agent 的认可替代实测。

### 7.2 必要对照

- 当前单 Agent 迭代。
- 单 Agent 自我反思。
- 提出 Agent + 质疑 Agent。

初期固定生成模型、知识条件和总预算，单独测角色分工；确认有效后再扩展模型和知识条件。相同模型扮演不同角色可能共享错误，需要通过反例与实际执行纠错，不能把多方一致作为正确性证明。

除了最终分数，还要记录：质疑是否具体、是否促成有效修订、是否误否定好假设、调用开销，以及失败恢复是否可靠。

## 8. 第三阶段：Jev 与决策方法

### 8.1 Jev 的候选用途

Jev 指 TypeSafe AI 的判断模型，可尝试将其概率或等级输出用于以下决策：

- 检索证据是否支持某条具体主张。
- 新提议是否与已探索思路重复。
- 当前证据是否足够，是否需要追加检索。
- 候选的评估优先级，以及失败后的修订方向。

现有流程没有逐候选的 LLM 裁判；可执行候选由真实下游评估打分。因此加入 Jev 会增加开销，必须验证节省的评估、检索或生成成本是否超过新增判断成本。若全部候选已实测，同一轮的最优分数可以直接由程序选择。

### 8.2 两周可行性预实验

1. **测量成本。**分解生成、检索、表达式执行与预测拟合耗时，识别真正值得优化的环节。
2. **旁路判断。**让 Jev 判断已有候选，只提供决策时可见的状态；隐藏候选真实收益、保留标记和未来反馈，暂不改变原流程。
3. **建立基线。**对比随机选择、简单规则或便宜的学习排序器、普通小模型判断、Jev 原始输出与校准后的策略。
4. **真实闭环。**有初步信号后重新运行搜索，评价改变决策后的完整轨迹。历史回放不能代替闭环，因为选择改变会影响后续生成。

Jev 置信度需要在开发任务上检验和校准。低置信度不直接等于低价值；为证据不足但可能新颖的候选保留探索预算。

主要指标：同总预算的最好分数、达到目标所需调用数、总费用与耗时、相对全评估策略的分数损失、高收益候选召回率和误拒绝率。报告需要计入所有模型与工具开销。

可事先约定一个内部继续目标，例如减少约 30% 的下游评估，同时保留约 95% 的基线改善量且总成本下降。该数值是待确定的项目目标，不是现有实验结果或发表保证；基线改善接近零时同时使用绝对损失指标。

如果简单规则同样有效，或真实瓶颈不在候选评估，应调整决策模块的作用位置或收缩 Jev 特定方案。

### 8.3 创新性边界

TypeSafe 官方已有自动特征发现示例，包含 LLM 提议、Jev 产生数值特征、预测模型反馈和迭代。仅将 Jev 接到材料任务上不足以确立方法创新。

分支更值得研究的是：科学探索中“判断可靠性、验证成本、漏掉新颖好假设”之间的权衡，以及该决策方法能否跨任务、跨提议模型使用。Jev 应作为可替换的判断组件，其效果需要与其他判断方法比较。

## 9. 其他优先考虑的创新方向

| 方向 | 具体改动 | 核心对照与证据 |
| --- | --- | --- |
| 失败反馈驱动的主动检索 | 根据失败原因和机制缺口生成下一轮检索问题；当前每种模式主要复用一次取得的证据包 | 固定证据、定期刷新、反馈驱动检索；匹配检索量与成本，观察新证据是否改变并改善假设 |
| 竞争假设与区分性验证 | 为同一现象提出不同机制，选择能区分解释的描述符或分析 | 比较只追求分数和显式区分机制的流程；审查预期差异是否被实测支持 |
| KG 关系的独立贡献 | 在匹配证据量、长度和内容的条件下控制图结构 | 纯文本证据、带关系证据、关系打乱等对照；先实现并验证打乱接口，不能把预留模式当作已完成能力 |
| 知识范围扩展 | 从沸石领域逐步加入 MOF/COF 等邻近领域，再研究跨领域机制迁移 | 区分知识数量、领域多样性与任务覆盖；固定数量对照，追踪跨域证据对假设的实际贡献 |

建议先选“主动检索”作为与当前工具链衔接最直接的扩展；竞争假设和知识范围扩展需要更明确的机制评价与数据支持。避免同时叠加所有组件后只汇报一个总分。

## 10. 评价边界与实施顺序

当前继续以单评分集衡量每次搜索的优化效果。训练部分仍然存在；评分集可以被循环使用，但应明确是自适应搜索分数。

为了评价 harness 能否迁移，应将开发控制规则的任务与最终评价任务分开：在开发任务上确定提示词、阈值和策略，再在未参与调节的新任务上评价。NCS／NMI 主线后续还需要独立的科学或跨体系验证。两个要求针对不同研究结论。

扩展阶段建议至少覆盖三个任务、两个数据来源和两个提议模型；这是实验设计建议，具体任务需通过数据可用性和科学适配审查。同一数据集的压力区间或多次随机生成不能自动算作独立 benchmark。

| 顺序 | 待办 | 完成标志 |
| --- | --- | --- |
| P0 | 保存当前基线；明确候选、假设、轨迹和成本字段 | 能追踪每个公式的来源、反馈与保留原因 |
| P1 | 配置化轮数并完成轮数、预算和反馈对照 | 得到收益曲线，明确主要失败与成本瓶颈 |
| P2 | 实现提出—质疑—工具验证流程 | 与同预算单 Agent、自我反思基线比较完毕 |
| P3 | 完成 Jev 旁路判断与小规模闭环 | 明确判断价值、误拒绝风险和实际成本收益 |
| P4 | 扩展任务与模型，选择主动检索等一个重点创新 | 完成迁移与关键组件消融，形成可支持的论文主张 |

此前讨论的“两周 Jev 预实验、约八至十周形成会议分支证据”属于工作量预估，依赖接口访问、数据准备和人员投入，不是已开始的运行日程。后续按阶段结果决定是否扩大投入，科学主线持续推进。
