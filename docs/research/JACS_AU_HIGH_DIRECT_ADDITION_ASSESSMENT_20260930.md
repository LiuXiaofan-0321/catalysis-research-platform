# high：从候选择优转向直接加入描述符的协议澄清

日期：2026-09-30。用户最新澄清：研究意图是每轮加入提出的描述符，不是每轮评分三个候选后挑最好一个。每轮加入数量可为1/2/3；当前提出每轮1个作为优先建议，尚未提交新实验。后续设计以此次澄清为准。

## 原结果的含义

每个实验重复使用同一原生14项D0、数据划分、目标换算、ANN 4000 epochs和fit seed=3。语言模型生成具有随机性（当前temperature=0.2，未固定供应商生成种子）；第二、第三轮还接收各自不同历史。因此同一D0并不意味着每次得到相同公式。

重复研究的是生成方法的可靠性，不是更换D0；这些重复不构成独立数据泛化验证。

V4的三组每轮都评分三个候选，评分预算相同，所以不直接偏袒某一组。但它测的是“生成＋复核＋ANN评分筛选”的整体效果，不能当成“不择优直接加入的假设质量”结果。评分择优且允许不加入任何描述符还保证保存的评分MAE逐轮不恶化；直接加入协议不具有这项保证。原V4完整结果继续保留为带筛选的历史开发实验，不改写排名。

## 现有数据能计算的无择优诊断

只取high第一轮：三个方法各三次完整实验的第一批三个最终公式，共每组9个、合计27个。全部27个都已单独以D0+一个公式评分，没有原先保留公式造成的reference差异。

把所有槽等权纳入，包含负收益，不挑保留槽、不设零收益下限，计算平均评分MAE降幅：

| 方法 | 9个第一轮公式的平均MAE降幅 | 平均评分MAE/R | 正收益槽 |
| --- | ---: | ---: | ---: |
| Agent | +0.4555% | 0.5729964 | 5/9 |
| RAG | +0.2807% | 0.5740021 | 5/9 |
| KG+RAG | +0.8038% | 0.5709912 | 7/9 |

D0评分MAE/R为0.5756182。观察排序为 **KG > Agent > RAG**，不足以支持 KG > RAG > Agent。

这一指标对应“从原三槽批次等概率取一个公式”的平均历史表现，既不是重新生成一个公式的试验，也不是同时加入三个公式的表现。三槽被要求覆盖至少两种机制，具有位置/机制分工；9个槽还嵌套于3个生成批次，不能当作9条独立完整轨迹。原复核也看过训练关联诊断。本分析是在看到旧结果后提出的探索性诊断，不能包装为预注册确认性实验。

为公开位置敏感性，完整报告固定位置均值，但不据它选位置：

| 方法 | h1均值 | h2均值 | h3均值 |
| --- | ---: | ---: | ---: |
| Agent | +3.2618% | −1.4404% | −0.4550% |
| RAG | +0.7879% | +0.2245% | −0.1702% |
| KG+RAG | +2.2264% | −0.4288% | +0.6139% |

h3位置恰好给出希望的排序，h1位置却为Agent > KG > RAG。事后挑h3会制造排名，因此不能这样做。全槽均值是完整保留已有数据的诊断，仍不能代替新协议执行。

## 为什么不能回算三轮直接加入的最终排名

第一轮每个公式的独立评分已有，但D0+三个公式的联合评分没有；联合效果有交互，不能把三个MAE降幅相加。

第二轮和第三轮是在历史择优组合上生成、复核和评分的。如果第一轮直接加入另一个公式，或者全部三个公式，后续输入组合、反馈、生成公式和ANN评分都会不同。不能把旧第二、第三轮记录拼成新的直接加入轨迹；固定某个槽的位置也不能修复这个问题。

## 建议的新主协议：high，每轮直接加入一个

1. 同一D0、同一划分和ANN；每组预先固定10个完整生成重复，各3轮，共30条轨迹、90个直接加入槽。每次重复三轮结束后得到一个最终MAE，每个方法用全部10个最终结果比较均值和波动。
2. 每轮只输出一个公式及其可证伪假设，不生成三个外部候选，也不训练多个公式来挑最佳。三组拥有相同的生成/复核阶段和修复预算。
3. 为研究知识辅助提出假设，RAG/KG在提出公式前即可看到相同已审查来源事实、出处与迁移条件；KG增加图表示。Agent得到相同D0变量定义、训练特征域和公共规则。不能让三组都先完全盲生成而将知识永久限于合规审查。
4. 定稿后直接加入当前组合，即使后来评分变差也不因MAE回退。三轮只追加：D0→D0+X1→D0+X1+X2→D0+X1+X2+X3。
5. 本主协议不把当前或历史评分MAE、候选排名、training_spearman、target_association提供给生成/复核，避免用标签反馈隐式搜索好公式。允许训练特征域、定义、数值有限性及局部公式方向检查；这不等于用预测表现选公式。阶段MAE可记录作诊断，但在公式冻结后计算，始终不送回生成环节。
6. 不可执行公式仅有一次训练前技术修复，仍失败保留失败记录，不抽新公式替代。执行前必须固定失败槽处理与完整总体汇总规则，不能只报告完成者而掩盖不同失败率。该规则及新单槽schema尚待实现和冻结。
7. 三轮最终组合才是主要比较对象，允许负收益。继续单独报告原外层开发诊断、HGB冻结公式迁移与科学一致性，不用它们代替主评分排名。

每轮加三个并非必然过多；三轮后增加9项会增加机制交互及解释难度。每轮一个先检验知识是否能提出有价值的单个描述符，归因更清楚；不能因为它更可能出现希望排序而选择。加入两个/三个应当作为事先冻结的独立协议，各组同数量，不根据结果挑最有利版本。

旧V4的三个重复不能补七条后冒充新协议的10条。新直接加入协议需要各组10条新轨迹；旧实验继续保留。若目标是同事实图表示的增量，还需graph/flat-graph控制；这个控制与三方法直接加入主比较分别报告。

- **缓存核查（同日追加）**：智谱[官方说明](https://docs.bigmodel.cn/cn/guide/capabilities/cache)描述自动复用重复输入的计算，并通过`usage.prompt_tokens_details.cached_tokens`报告命中；这不同于复用完整答案。旧合并轨迹125条已记录尝试中，101条报告0、23条报告64、1条报告3840个缓存输入token。high共64条记录、896个缓存输入token，占报告输入token约0.173%；同档首轮9个盲生成请求完全相同，9份结构化响应均不同。现有记录未显示首轮重复统一返回同一答案，但不能据此保证未来端点、代理或服务实现没有任何缓存影响。详见[缓存审计](../../research/reports/jacs_au_kg_v4_diagnosis_20260930/cache-audit.json)。这些是合并记录用量，包含历史回放事件，不是本次新调用账单。
- **新实验前置核查**：同一正式提示、同一high采样设置连续调用5次作为工程预检；保存服务返回的id/request_id/created（若提供）、缓存usage、耗时、原始答案与公式重复情况。每个科学重复重新请求API，不把恢复回放当作新的重复；清楚区分恢复已有事件与新生成。若发现响应标识/整段答案异常复用，先检查代理/官方端点并保留异常记录，不能换提示反复请求直到得到希望排名。若只是公式相同，则可能反映生成分布集中，重复照样保留并报告不同公式数。不要通过在科学提示中加入随机字串、时间戳或“不得重复旧公式”来强制多样性；这会改变实验条件，且不保证关闭供应商输入缓存。唯一追踪标识若使用，只放在官方支持的请求元数据中，并先验证支持情况。`clear_thinking=true`和换request_id均不应被当作关闭上下文缓存的保证。
